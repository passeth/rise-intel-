## 4. 핵심 패턴

### 4.1 인증/인가 (RBAC)

- 미들웨어: `@supabase/ssr` 세션 갱신 + 보호 라우트 리다이렉트
- 역할: `admin`, `production_manager`, `materials_manager`, `manufacturing_team`, `viewer`, `pending`
- 권한: resource별 `can_view`, `can_create`, `can_edit`, `can_delete`
- SSR 최적화: 서버에서 유저 프리페치 → `UserProvider.initialUser`로 전달

### 4.2 데이터 페칭

```
feature 디렉토리/
  ├── page.tsx        ← 'use client' + useQuery/useMutation
  └── actions.ts      ← 'use server' Server Actions
```

- 모든 페이지: 클라이언트 컴포넌트
- 데이터: Server Actions 경유
- 캐싱: `staleTime: 0`, `gcTime: 5분`

### 4.3 AI 통합

1. `claude.ts` — 싱글톤 클라이언트
2. `report-prompts.ts` — 9종 프롬프트 템플릿
3. API Route — DB 컨텍스트 수집 → 프롬프트 빌드 → Claude 호출 → DB 저장

리포트 8종: Deep Dive, Efficacy, Compatibility, Regulatory, Stability, Formulation, Clinical, Trend (+Formula Analysis)

## 5. 코드베이스 건강도

### 강점

- TypeScript strict 모드
- Supabase 생성 타입 활용 (`Database` 제네릭)
- 서버 유저 프리페치 (SSR 최적화)
- Server Actions + TanStack Query 패턴 통일
- AI 리포트 병렬 쿼리 (`Promise.all`)
- RBAC 완비
- 일관된 파일 구조 (`page.tsx` + `actions.ts`)
- `as any` / `@ts-ignore` 없음

### 개선 필요

| 항목 | 현황 | 제안 |
|---|---|---|
| 테스트 없음 | 0개 | AI 리포트, 인증 최소 테스트 |
| 하드코딩된 통계 | 홈 대시보드 `1,571` 등 | DB 동적 조회 |
| 미들웨어 경고 | Next.js 16 deprecated | `proxy`로 마이그레이션 |
| 타입 캐스팅 | `role_permissions as 'user_roles'` | Supabase 타입 재생성 |
| PDF 유틸 분산 | `fonts.ts`만 존재, 생성 로직 컴포넌트 내 | PDF 레이어 통합 |
| 에러 바운더리 없음 | `error.tsx` 부재 | 추가 필요 |
| loading.tsx 없음 | 각 페이지 직접 처리 | Suspense boundary 활용 |
| Zustand 미사용 | 의존성만 존재 | 제거 또는 구현 |
